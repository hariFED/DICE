problem 02 / 12
01

Software VRFs live or die
on one private key.

Every major randomness oracle on Solana today relies on a single cryptographic key held by an operator. If that key leaks — or the operator misuses it — they can bias every lottery, every mint, every raffle that depends on them. The entire trust model reduces to: please don't mishandle this one file.

solution 03 / 12
02

We generate randomness
in silicon.

Each DICE node is a physical ESP32-S3 module. The chip contains a hardware true-RNG that samples thermal noise — not derivable from any algorithm or prior state. The value is signed by a key the chip generated itself and never exposes.

Nobody, including us, can reveal a key we've never seen.

REQUEST

04

Program XORs the bytes, signs the result, delivers to your callback.

architecture · overview 06 / 12
05

ESP32 mesh →
stateless coord →
Solana program.

The coordinator is a relay. It can't sign, can't sample, can't choose. Nodes speak mTLS directly to it; the program on Solana verifies every reveal. If the coordinator disappears tomorrow, operators continue to earn from a replacement spun up in minutes.
