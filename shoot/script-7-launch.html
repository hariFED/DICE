DICE — Product Launch

Clean. Professional. No jargon. No founder story. Just: what is it, why does it exist, how does it work, what's coming next.
Runtime: ~90s Flow: what → why → how → future

What is it 0:00

Open on the DICE logo. Clean white. Hold 2 seconds. Then the logo moves to the corner and the speaker appears.
FACE — centered, clean frame, direct to camera. No warm-up. First word is the product.
"DICE is a hardware network
that produces verifiable randomness for Solana."
beat
"Physical devices. Real entropy.
Delivered on-chain in a single transaction."
Four lines. The audience now knows: it's hardware, it makes randomness, it's on Solana, it's fast. No backstory needed. No "we built this because." Just: this exists. Here's what it does.

Why it exists 0:10

"Every on-chain game, every lottery, every NFT mint
needs a random number it can trust."
"Today, that number comes from cloud servers."
Simple visual: a single server icon with lines going to multiple app icons. Looks fragile. Centralized. One color. Muted.
"One operator. One point of failure.
One place where the entire system has to take
someone's word for it."
beat
"DICE replaces that with hardware."
Clean pivot. No emotion. No "that's not decentralized." Just: here's the problem, here's the replacement. The professionalism IS the confidence.

How it works 0:25

Hold up the ESP32. Let the camera see it clearly. Then set it on the desk next to the other three.
"Each node is an eight dollar microcontroller
with a cryptographic key permanently embedded in the chip."
"It can't be copied. It can't be extracted.
It can't be cloned from a backup."
Close-up render of the ESP32-S3. Two callout labels appear simply: "Hardware Key" and "Physical Entropy." No other labels. Clean.
"The device generates entropy
from electrical noise inside the hardware itself."
"Multiple nodes run together.
Each one commits a value independently.
No node sees another's value until all are locked in.
Then they reveal at the same time."
4 nodes → 4 sealed values (lock icons) → all locks open simultaneously → values merge → one output. 4 seconds. Geometric. Satisfying.
"The result is a random number
that no single node, no single operator,
and no single company could have influenced."

The numbers 0:48

Three stats appear one at a time on a dark background, Apple keynote style. Each one holds for 1.5 seconds: "1 transaction" "3.5 seconds" "10 lines of code"
"One Solana transaction — commit, reveal, finalize — all bundled.
Three and a half seconds end to end.
Ten lines of code to integrate."
"And something no other provider on Solana offers —
streaming randomness.
Subscribe once. Values arrive continuously."
Stream of values flowing smoothly from device cluster into a simple app interface. Continuous. Clean motion.

What's next 1:02

This is where the video expands from "VRF product" to "infrastructure platform." Same calm energy. No hype. Just: here's what the same device does next.
"Randomness is the first service.
It's not the last."
Two lines that reframe everything. "First" and "not the last" — the audience recalculates what DICE is.
"The same device, the same key, the same network —
can verify location without GPS."
The ESP32 node in center. "Location Proof" label lights up next to the already-lit "VRF" label. Visual: nodes triangulating each other's positions via Bluetooth signals. Lines between nodes. Position confirmed.
"It can sign real-world sensor data —
temperature, air quality, energy output —
with a key that proves the reading came from hardware,
not a spreadsheet."
"Sensor Attestation" lights up. Visual: small sensor icon plugging into the ESP32. A signed data reading flows to the Solana logo. Simple.
"And it can act as a distributed hardware signer —
the security of a fifty thousand dollar module
from a five dollar chip."
"Hardware Signing" lights up. All four service labels now visible around the device: VRF .............. (white — live) Location Proof ... (grey — next) Sensor Data ...... (grey — next) Hardware Signing . (grey — next)
